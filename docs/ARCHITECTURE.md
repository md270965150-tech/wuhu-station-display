# 架构演进与关键决策

本文描述历史设计，不包含厂商接口地址、鉴权参数、账号或真实车辆样例。代码文件名只是定位线索，不表示源码已随本文公开。

## 1. 边界与职责

厂家系统提供车辆识别与事件。B30负责浏览器公众展示、播报调度、辅助资讯、记录与导出。订单准入、道闸控制和厂商数据库仍是外部职责。

主干逻辑可读为：

车辆SSE → 事件解析/同趟识别 → 大屏模型与记录采集 → 语音任务/播放许可 → 音频执行与真实开始/结束回执

天气、新闻、官方预警与节日文案属于辅助内容，不改变车辆是否在场的判定。

## 2. 数据来源：从双来源风险到仅SSE

早期浏览器扩展曾存在页面DOM识别分支。现场发现同一趟可能被SSE和DOM分别建任务，单纯增加播放层去重不能证明所有来源重复已经解决。

1.8.6明确停止生产页面扫描器，后台拒收页面来源入场/离场/基线事件；断线时也不回退DOM。原DOM解析器只作为历史测试保留。取舍是统一事实来源，同时必须如实记录断线缺口。

首次加载/重连快照建立基线而保持静默；后续快照中新增车辆的视觉提醒另行处理。屏幕15分钟静默隐藏只是显示生命周期，不能制造“真实离场”。`carclose`关闭证据也不能直接代替`carout`或可靠实际离场证据。来源：S04、S06、S07。

## 3. 语音链路：成功经验不能只看版本号

### 早期R8

当时确认的成功路径为：扩展/Offscreen → Service Worker → Chrome Native Messaging → Native Host1.4.4 → 本机Bridge1.3.2 → 自然语音上游。

复盘记录的关键点包括HTTP 101握手、空子协议值、完整音频字节返回及句式插值修复。单次关闭代理并未解决问题；不能把某个尝试当作唯一根因。测试直接调用Host有成功新合成和用户听音证据，但不自动覆盖实际Chrome调用。

### B区扩展与回归本机链路

1.7.3–1.7.6为B区加入浏览器WSS整句合成和独立缓存，但模拟WebSocket通过不能证明现场握手成功。1.7.7重新使用R8有效传输实现，升级A/B协议能力。

- zone仅接受A/B，固定目的地句式在可信服务端构造
- 旧A-only服务不能把B请求默认为A
- A/B缓存、解码与在途去重带分区/句式配置身份
- A区预生成音频含A区目的地，不能拿给B区使用
- A/B合成进程独立，共享扬声器仍串行
- 合成完成后、真正播放前重新核对趟次、离场、开关及页数门槛

1.7.9 R2继续解决Windows部署约束，将安装器与常驻Bridge改为EXE，后续扩展版本沿用已验证组件，而不是每次升级都要求重装。来源：S04、S05、S07。

### R1瘦身直装

去除预生成车牌整句库后，R1仍保留“整句自然语音 → 本地基础片段拼接 → 系统TTS”的兜底链。73条基础片段不是预生成车牌库。能播放缓存、片段或系统TTS，均不能据此宣称当时上游新合成成功。

浏览器直装解决的是扩展加载便利性，不表示无需本机Native服务。来源：S08。

## 4. 调度：公平、延迟与完整次数

调度历史经历了几次明确修正：

1. 区内新车首播优先，曾导致另一区旧车复播饥饿
2. 1.8.3删除积压时削减剩余次数，分区仲裁并保持完整一句
3. 1.8.8强化完整轮次交替，但对未到时轮次的等待带来首播空等问题
4. 1.8.9先判断当前可播任务，所选区内首轮优先
5. R1限制连续新车优先，兼顾旧车到期复播，并恢复后台重启后的轮次状态

始终保留的约束：正在播放的完整句子不能被另一分区抢断；成功完成才计播放轮数；离场、关闭、有效期、页数门槛和失败均可能依法取消剩余轮次，不能为了凑设置次数继续播报已离场车辆。

1.8.7之后，B区超页数只允许已出声的当前句完成；尚未出声及后续轮次取消，回落不补积压。真实离场走450ms音频渐出，释放共享扬声器前不得重叠；系统TTS因接口限制仍立即停止。来源：S07–S09。

## 5. 生命周期与恢复

1.8.4重点处理音频页空闲回收竞态、operation/attempt身份、播放许可提交后的不确定状态和有限等待。无法确认旧任务停止时，不能盲目重播兜底。

1.9.0/R1进一步把“任务已持久接收”与“全部播完”分开确认，加入同事件补送、恢复日志、在场清单验证、旧后台命令拒绝和迟到写入防护。诊断写入不得无限阻塞主播报队列。

无法确认是否已出声的轮次采取保守取消而非自动重播。页面关闭前尚未获得后台确认的消息不承诺跨页面永不丢失，旧版纯内存任务也不会被升级凭空恢复。来源：S07–S09。

## 6. 记录与Excel

记录模块从1.7.4独立发展。公众屏仅皖B的显示范围不应限制原始A/B全部车辆采集。配对依赖可靠厂家时间/身份和连续采集证据，无法判断时保留缺口或待核实，不用其他趟次填空。

1.7.11对可靠闭合行程的重复快照观察做归并，并保留原始事件及追溯信息；1.8.1区分关闭与实际离场；1.9.0/R1补跨日状态、采集缺口晚到、导出期间事件与历史状态更新。

统计必须区分：生成一条自然音频、从缓存使用一轮、完整播放一轮。合成成功后取消可以增加合成数，不能增加播放轮数；试听不混入生产播报统计。来源：S04、S06–S09。

## 7. UI、天气与新闻

- B左蓝/A右橙、完整车牌、每区8辆、独立分页是持续保留的导视骨架
- 静默到场提示与实际出声提示分离，声画联动以音频回执为准
- 历史单行/语义分页方案最终演进为短标题正常单行、溢出缩小两行、同题不分页
- 官方预警优先，普通提醒不伪装成预警；查询失败不等于确认无预警
- 随包官方备用原图只明确覆盖雷电黄/橙/红三种，不能宣称全灾种离线库
- 地下B1场景不能从室外温度推断室内温度，节气名称也不能当作实时天气

1.9.1主题与提醒层在此基础上开发；概念图不证明已经完成集成。来源：S03、S07–S11。
